ДОМОВОЙ — ручная работа с контроллерами

Запуск: двойной щелчок «Запуск_сервера_Нависет.pyw».
Нужен Python 3.11+ с tkinter. Для встроенного просмотра JPEG нужен Pillow
(requirements-naviset.txt); в рабочем Python 3.11 он установлен.
Повторный запуск ярлыка открывает существующее окно этого сервера.
Прежний сервер и новый одновременно порт 15010 занимать не могут.
Прежний сервер автоматически не выключается. Реальные платы не перенастраиваются.

1. На главном экране «Проверка платы» выберите контроллер слева и нажмите
   «Проверить плату». Проверяются связь, ответ статуса, время и чтение CRC.
   CRC только читаются: совпадение с эталонной конфигурацией не проверяется.
   Проверка не запускает выходы, SMS, сброс или обновление прошивки.
   Результат и TXT/JSON-отчёт сохраняются по IMEI в Логи/adapter/reports.
   «Открыть отчёт» открывает текстовый результат; последняя проверка доступна
   после перезапуска сервера с пометкой результата прошлого подключения.
   Проверку можно остановить. При обрыве связи нужно запустить её заново.
   Подключившиеся платы появляются по IMEI автоматически.
   Можно заранее добавить IMEI, название и объект; это локальная серверная копия.
2. Контроллер: статус, CRC, время, перезапуск, выходы, режимы, Wiegand, SMS.
   «Применить режимы» отправляет ВСЕ выбранные переключатели, включая SMS.
   Статус платы сообщает первые четыре режима; остальные нужно задать явно
   или восстановить из сохранённых значений этого стенда.
3. Доступ: добавляйте и редактируйте ID, группы, расписания, праздники.
   «Сохранить запись» меняет только серверную копию.
   «Сохранить и синхронизировать» передаёт выбранную структуру на плату;
   для отключённой платы снимок сохраняется до её регистрации.
   ID передаются порциями по 32. Номер ячейки сохраняется; удаление ID —
   истёкшая дата запрета, без перенумерации оставшихся записей.
   Группы — полный снимок из 64 ячеек; отсутствующие группы заблокированы.
   Расписания — 1–64 записи по 16 байт + общий хвост 16 байт, сцены индивидуальны.
   Праздники — текущий год, 1–128 дат. Пустой список прошивка не принимает.
4. Настройки: сначала загрузите актуальную USB-копию config_s, 512 байт с CRC.
   Затем измените адреса серверов, APN, сеть, Wiegand, режим и периферию 485.
   Неизменённые поля копии сохраняются. Сервер не умеет читать config_s по TCP:
   такой команды нет в предоставленном протоколе.
   «Линия RS-485: что включено» — восемь строк: устройство из справочника
   periphery.ini (типы группами по 8: 1 Wi-Fi, 8 камера номеров Interceptor,
   9 фотокамера JPEG, 16 кодовая панель Tantos, 24 RFID AXOS) и адрес 1–255.
   Камера номеров — адрес 48 (в её настройках serialAddr 48, символ «0»).
   Устройства по адресам работают только в режиме «Активный опрос»; повтор адреса
   и адрес 0 сервер не отправит. Wi-Fi-модем включается на плате по USB (NextConfig),
   а не этой таблицей; пока он выбран, линия 485 занята мостом.
   Колонка «Сейчас» — ответы устройств по последнему статусу 2 («отвечает» /
   «нет ответа»); обновить — кнопкой «Обновить «Сейчас» (статус 2)».
5. Прошивка: выберите HW.FW.BUILD.bin, затем «Обновить прошивку».
   Проверяется HW, размер, совпадение установленной сборки (если статус получен).
   Отданные блоки, новая сборка и событие 136 показываются отдельно.
   Откат запрашивается отдельно; наличие резервной копии решает контроллер.
6. Фото и журнал: снимок камеры, получение фото, встроенный экран последнего
   полного JPEG выбранной платы. Фото появляется автоматически после получения;
   рядом указаны время и разрешение. Двойной щелчок или «Оригинал» открывает файл.
   При смене платы снимок переключается. Повреждённый JPEG отмечается ошибкой.
   Журнал событий показан под фото. Журнал и принятые байты фото сохраняются на диске;
   повторные записи журнала не добавляются, фото продолжается с сохранённого места.
   Подтверждение всей очереди фото отправляется после её окончания и записи файлов.
   Адрес камеры по умолчанию — первая камера (тип 8 или 9) из копии настроек.
   Блок «Камера номеров Interceptor»: «Считать номер с камеры» — команда 6
   (источник 485, адрес камеры, 15 с), ответ — пакет 8 с номером; строка над
   кнопками показывает считанный номер и отвечает ли камера по статусу 2.
   «Добавить номер в базу…» открывает форму ID «Автономер» с этим номером;
   ячейку и группу выберите сами, затем «Сохранить и синхронизировать» в «Доступе».
   Номер хранится как его отдаёт камера: латиницей, заглавными, хвост — нули до 10 Б;
   русские буквы АВЕКМНОРСТУХ переводятся в латинские сами.
7. Очередь: результат каждой команды; «отправлено» не означает «выполнено».
   Задержки можно менять вручную для выбранной платы; TTL при этом продолжает идти.
8. Обмен: читаемый текущий лог. «Сохранить логи в ZIP» слева — архив выбранной
   платы: точные входящие TCP-байты, исходящие кадры, разобранные команды,
   время UTC и монотонное время, номер сеанса, состояние очереди, параметры
   обмена, серверные данные, журнал в SQLite и полученные фотографии.
   Логи содержат настройки и ID платы; архив предназначен для вашего разбора.

Проверка камеры номеров (Interceptor, прошивка с b238657)
  1. Камера: loop 0 (по запросу), serialAddr 48, serialSpeed 115200; после правки
     её конфига — перезагрузка по питанию, распознавание поднимается ~1 мин.
  2. Провода A/B камеры — на 485 платы. Мост Wi-Fi на плате снять (NextConfig, «Связь»)
     и отключить от линии: с выбранным мостом прошивка камеру не опрашивает.
  3. Плата на этом сервере. «Настройки»: «Режим RS-485» — «Активный опрос»,
     строка 1 — «8 — камера номеров», адрес 48; «Сохранить и отправить настройки».
     Плата спрашивает номер раз в секунду; «Сейчас» у строки — «отвечает».
  4. Номер в кадре → «Фото и журнал» → «Считать номер с камеры»: номер появится в строке
     блока и событием 78 в журнале.
  5. «Добавить номер в базу…» → ячейка, группа с «Автономер» → «Сохранить и синхронизировать».
     Реле в настройках платы должны разрешать «от камеры». Машина в кадре → проход:
     событие 73, реле щёлкает; тот же номер повторно — только после 15 с без него в кадре.
     Номера нет в базе — событие 65.
  6. Снимок: по проходу сам; вручную — «Сделать снимок», пока номер в кадре
     (без номера в кадре камера снимок не отдаёт, плата ответит «ошибка выполнения»).
     Фото ~42 КБ приходит сюда автоматически, событие 129.

Где сохраняются данные
  Логи/adapter/controllers.json — серверные данные и заказанные снимки структур.
  Логи/adapter/<IMEI>.sqlite3 — команды, исходы и журнал (таблица journal).
  Логи/adapter/traffic/<IMEI>_<дата UTC>.jsonl — точный обмен для разбора.
  RX/chunk — оригинальные байты TCP (сохраняют реальный TTL, мусор, разбиение).
  RX/decoded — успешно разобранная команда; TX/frame — реально отправленный кадр.
  Логи/adapter/photos/<IMEI>/ — принятые части и курсор продолжения фото.
  Фото_с_камеры/<IMEI>_<номер>.jpg — полностью принятые файлы.

Что воспроизводится
  Регистрация за 5 секунд, статус раз в пределах 30 секунд, ответы 1/24.
  Очередь каждого IMEI независима; новое соединение того же IMEI вытесняет старое.
  Четыре приоритета, TTL, сопоставление ответа с uniq и командой.
  Резервирование полного размера отправленного кадра; статус/ответ 11 обновляет
  свободное место. Учёт намеренно консервативный, без переполнения буфера.
  Во время FW останавливаются синхронизация, запросы и управление выходами.
  Синхронизация структур последовательная, запросы ждут её окончания.
  Новый запрос 13 освобождает прежний блок 20 даже без ответа 4.
  Сохраняются очередь и исходы. Неотправленные команды живут до TTL;
  отправленные без ответа после обрыва получают «результат неизвестен».
  Сбросы, реле и SMS автоматически повторно не выполняются. Идемпотентные
  снимки структур могут возобновляться после регистрации.

Источники и границы соответствия
  User story (6).xlsx: «Протокол2» A61:C65 (сеансы), A72:C73 (TTL/uniq),
  A80:A97 (синхронизация/приоритеты), A110:F132 (команды), A280:E361 (структуры),
  A429:E568 (ответы). «Требования к адаптеру», строки 4–23.
  Приложенная переписка: 23.09, 14:43 — освобождение места при следующем запросе FW.
  Это функциональная модель части управления контроллерами по доступным материалам,
  не копия их закрытого исходного кода, сайта, БД, Kafka, ролей или тарификации.
  Автоматического управления выходами/SMS в диагностике нет.
  Реле, считыватели, камера, звонки и SMS требуют отдельных ручных проверок.
  Сопоставление CRC с полной серверной БД и автоматическое исправление всех
  несовпадений, межконтроллерные счётчики проходов и смена календарного года
  не реализованы. CRC можно запросить вручную; синхронизация — явной кнопкой.
  Настройки из файла — снимок, а не прочитанные по сети текущие значения платы.

Разночтения источников не скрыты
  В строке 129 ошибочно стоит команда 10; используем 20 по описанию и переписке.
  TTL блока: в таблице 10 с, в пояснении 20 с. По умолчанию 10, настраивается.
  Коррекция времени: в описаниях 60 и 300 с. По умолчанию 300, настраивается.
  Фото: Excel A184:E185 — 7+адрес; текущий user_commands.c — только адрес.
  В форме камеры есть выбор формата. По умолчанию «ДОМОВОЙ NEXT»: один байт
  адреса, как принимает текущий user_commands.c. Для табличного формата выберите
  «Протокол2». Адрес и формат сохраняются отдельно для каждого IMEI.
  Одновременные платы за одним NAT не блокируются только по общему IP.
  Масштаб 5000/10000 контроллеров не заявляется: это локальный стенд.

Дополнительные условия обмена (не обязательны для обычной работы)
  python -X utf8 naviset_server.py --adapter-profile profile.json
  JSON, только нужные поля, например:
  {"firmware_delay":14,"firmware_ttl":20,"fragment_size":32}
  Также: command_delay, drop_status_every (каждый N-й ответ 24 пропустить),
  corrupt_block (один раз испортить данные указанного блока), stop_after_blocks,
  disconnect_after_blocks, allowed_imeis (список строк), time_drift_limit,
  registration_timeout, heartbeat_timeout, photo_retry, photo_stream_timeout.
  По умолчанию неисправности выключены.
  --adapter-state КАТАЛОГ меняет папку серверной копии; --log-dir КАТАЛОГ — логов.
  --bind 127.0.0.1 --port 0 --control-port 0 — изолированный локальный запуск.

Архив для проверки снимается кнопкой в интерфейсе. Основной ярлык и автозагрузка
этой машины запускают Нависет. Прежний test_server.py остаётся зависимостью
протокола; удалять его исходник не следует.

Проверки протокола (один сервер для ручной работы и прогонов, 23.10.2026)
  Нависет выполняет все проверки checks.py на выбранной плате, отдельный
  test_server.py для этого больше не нужен. Из каталога Скрипты:
    python ctl.py state                  плата, сеансы, флаги статуса
    python ctl.py run all                безопасные проверки
    python ctl.py run full server1=176.212.122.196:15010 config=..\Логи\<копия>.bin firmware=..\Прошивки9.71.<сборка>.bin phone=79..
                                         все, включая синхронизацию, проходы, SMS, фото, перезагрузку, обновление
    python ctl.py run проходы перезагрузка   выбранные проверки
    python ctl.py run тяжёлая_база       тяжёлые проверки только по имени (3000 ID)
    python ctl.py journal 20 | reload | peers | use <IMEI>
  server1= обязателен для синхронизации настроек: в плату пишется адрес этого
  сервера, иначе плата ушла бы на адрес из файла копии (так было 23.10 с gate).
  Ответ 11 разбирается по Протоколу2: код, время, буфер; команда — по uniq.
  Как у сервера NAVISET: статус с битом 15 (заводские настройки) — один раз за
  сеанс команда 3 (обнуление). Выключить: профиль {"factory_on_default": false}.
