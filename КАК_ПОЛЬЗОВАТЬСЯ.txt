СКРИПТЫ СТЕНДА DOMOVOI NEXT
Порт везде COM5. Если плата на другом порту, поправить '\\.\COM5' в начале скрипта.
Перед запуском закрыть NextConfig и старый конфигуратор: порт может держать только одна программа.
Запуск: python "путь\скрипт.py" аргументы

ПЛАТА В СТАРОМ ЗАГРУЗЧИКЕ 2.1 (протокол SLGT)
Вход: снять питание полностью (12 В и USB), 5 секунд, зажать кнопку у R22/C25,
подать 12 В, через 2-3 секунды отпустить, подключить USB. Светодиоды мигают по очереди.

boot_probe.py
  Только чтение. Спрашивает у загрузчика идентификацию (0x00) и проверку CRC флеш (0x15).
  Ответ 0x00: 00 21 8B ... = режим загрузчика, версия 2.1, HW 139.
  Ответ 0x15: 00 = образ во флеш цел, 02 = CRC не сошёлся.

boot_flash.py ПАКЕТ [--go]
  Без --go только проверяет пакет моделью загрузчика и ничего не шлёт в плату.
  С --go записывает: 0x00, 0x10, 0x12 стирание, 0x13 заголовок, 0x14 блоки по 1024, 0x15 CRC, 0x11.
  В конце должно быть "CRC check on board: OK" и "DONE".
  Перезагрузку командой 0x04 не шлёт намеренно. После записи снять питание и включить без кнопки.
  Пакеты лежат в папке Прошивки, берутся файлы "..._для_старого_загрузчика.bin".
  Запись 60 КБ занимает около 5 секунд. Если оборвалось, плата остаётся в загрузчике, повторить.

boot_read.py flashsize
  Только чтение. Регистр объёма флеш 0x1FFFF7E0. На плате №1 показывает 128 КиБ.

boot_read.py dump АДРЕС РАЗМЕР ФАЙЛ
  Только чтение памяти командой 0x16, по байту, ~22 байта/с (32 КБ за 25 минут).
  Если файл уже есть, докачивает с места обрыва.
  Пример: python boot_read.py dump 0x08000000 32768 загрузчик.bin

ПЛАТА С РАБОЧЕЙ FW NEXT (протокол SLDN)

boot_replace.py ЗАГРУЗЧИК.bin [--apply]
  Замена загрузчика через работающую прошивку, команда 110. Нужна прошивка ec76d4b
  или новее (FW 50): FW 49 файл 0x32 не примет.
  Без --apply: загружает файл во внешнюю флеш, прошивка его проверяет, затем отмена.
  Ничего не заменяется, этим проверяется передача.
  С --apply: прошивка переписывает 0x08000000-0x08007FFF из RAM и перезагружается.
  БЕЗ ST-LINK НЕОБРАТИМО: пропало питание посреди записи - плата мертва до программатора.
  Старый загрузчик 2.1 после этого не вернуть без программатора.


next_status.py
  Выключает отладочный вывод (108 = 0) и читает пакет состояния (101):
  время, csq (сигнал), creg (сеть), cgreg (интернет), connected (сервер).
  Регистрация в сети занимает около 2 минут после включения.

next_log.py СЕКУНДЫ БИТЫ ФАЙЛ
  Включает текстовый отладочный вывод прошивки и пишет его в файл.
  Биты: 1 обмен с модемом (AT-команды), 2 события GSM, 4 общие события. 7 = всё.
  Пример: python next_log.py 60 7 лог.txt
  ВАЖНО: после него обязательно запустить next_status.py (он выключает вывод).
  Если закрыть порт с включённым выводом, прошивка зависает на передаче и через ~10 с
  перезапускается сторожевым таймером.

next_monitor.py СЕКУНДЫ
  Раз в 5 секунд читает состояние и пишет строку. Удобно смотреть выход в сеть после включения.

next_watch.py
  Ждёт, пока плата пропадёт и снова появится на COM5 (передёрнули питание),
  и сразу шлёт запрос опознания (100). Печатает IMEI и признак заводского PIN.

read_config.py [ФАЙЛ.bin]
  Только чтение. Настройки платы (106): адрес серверов, APN, тип сети. CRC настроек проверяется.
  С аргументом сохраняет 512 байт настроек в файл.

watch_fw.py СЕКУНДЫ [--diag] [--now]
  Опрос 101 раз в 3 с; с --diag ещё 111 (FW 64+). Без --now ждёт передёргивания питания.
  С FW 65 печатает строку «111 regs»: регистры USB при последнем срабатывании сторожа и сейчас.
  tx=NAK и txstate=1 — потеряно прерывание «пакет забран» (ошибка прошивки);
  tx=VALID — пакет готов, а компьютер его не запрашивает (драйвер или хост).
  Вывод не фильтровать: строки «no answer» и есть результат.

ЧЕГО НЕ ДЕЛАТЬ
Загрузчику не слать 0x18 и 0x1A (защита флеш, стирание всего).
Не нажимать в NextConfig "Обновить" у загрузчика и FW, "Сброс на заводские",
"Установить по умолчанию", "Очистить", "Отвязать контроллер", "ТЕСТ" у выходов.
Кнопка "USB<->GSM" ничего не делает (команда 107 в прошивке не реализована).

ФОТО C328 — ЛОКАЛЬНЫЙ СТЕНД (23.09.2026)

1. Сервер с окном:
   python photo_server_gui.py
   По умолчанию слушает 0.0.0.0:15010. Для другого порта:
   python photo_server_gui.py --port 15011
   Нажать «Старт сервера». Контроллер должен подключаться к IP этого ПК и выбранному TCP-порту.
   Для внешнего подключения настроить проброс TCP 15010 на этот ПК, как для fw_server.py.
   Одновременно два сервера на одном порту не запускаются: остановить fw_server.py либо выбрать другой порт.
   Настройка платы, роутера и брандмауэра автоматически не меняется.

2. Камера без камеры:
   Закрыть программы, использующие COM-порт свистка USB-485.
   Свисток A → X1.1 A платы; B → X1.2 B. Соблюдать требования адаптера к общей земле.
   Нужен USB-485 с автоматическим направлением; UART 115200, 8N1.
   Запуск (COM8 заменить на порт именно свистка, не USB платы):
   python camera_emulator.py --port COM8 --baud 115200 --file sample_640x480.jpg
   Пример sample_640x480.jpg — настоящий JPEG 640×480, ровно 50 КиБ, без внешних ресурсов.
   В конфигурации платы должна быть активная шина 485 (rs485Mode=1), периферия типа 3
   с адресом 1–255. Адрес выбрать тот же в окне сервера; в протоколе C328 адреса нет.
   Эмулятор не записывает прошивку и не меняет конфигурацию платы. Ctrl+C завершает эмулятор.

3. Проверка:
   Выбрать IMEI в списке → указать адрес камеры → «Сделать снимок».
   Снимки в одну секунду получают разные последовательные номера.
   После завершения съёмки/появления бита 13 нажать «Забрать фото».
   Во время бита 11 (обновление FW) съёмка и выгрузка запрещены.
   «Стоп» останавливает новые запросы выгрузки; уже отправленный запрос может завершиться.
   Готовые JPEG: Стенд_Domovoi\Фото_с_камеры\<IMEI>_<номер>.jpg.
   Журнал: Стенд_Domovoi\Логи\YYYY-MM-DD_photo_server.log.
   Если установлен Pillow, фото показывается в окне и проверяется декодером.
   Без Pillow проверяются FFD8…FFD9, файл сохраняется и открывается системным просмотрщиком.
   При необходимости: python -m pip install Pillow. Сервер и COM-эмулятор обходятся без иных зависимостей.

4. Помехи:
   Настройки выбрать перед «Забрать фото»: терять каждый N-й пакет 14 (0 — выключено),
   повторять запрос с новым uniqId, задерживать следующий запрос на указанное число секунд,
   разорвать TCP после получения половины фото (один раз на выгрузку).
   После искусственного разрыва сервер продолжит с сохранённого смещения при переподключении платы.
   При потере ответа повтор выполняется через 5 с. N=1 специально теряет все ответы до «Стоп».
   Параметры эмулятора:
   --silent             не отвечать вообще;
   --error-packet 10     портить verify пакета №10 (нумерация с нуля), включая повторы;
   --delay 0.02          задерживать каждый ответ на 20 мс.
   Задержка больше таймаута камеры приведёт к ошибке съёмки, это ожидаемая помеха.

5. Протокол этого сервера и новой FW:
   Команда 21 без аргумента возвращает первый неподтверждённый блок.
   Явный запрос: <номер фото uint32 LE><смещение uint16 LE>.
   Подтверждённые байты повторно не выдаются: 0/0 начинает с первого неподтверждённого места.
   uniqId — только метка ответа.
   Смещение=размер подтверждает целое фото и переключает на следующее.
   Повтор запроса безопасен, включая потерю последнего ответа и повтор подтверждения.
   Чужой номер/смещение за размер при непустой очереди дают ответ 11 с кодом 1;
   сервер повторяет 21 с 0/0. При пустой очереди любые аргументы дают ответ 11 с кодом 0
   и один пакет 14 со счётчиком 0, без повторного стирания Flash.
   После сброса контроллера сверка начинается с первой сохранённой записи: сервер при необходимости
   принимает её заново. Файлы с одинаковыми IMEI/номером заменяются только целым проверенным JPEG.
   Старый сервер без аргументов больше не продвигает курсор автоматически — будет повторять блок.
   Обновление FW в fw_server.py не изменялось. «Протокол2» не редактировался.

Проверено программно: Python C328 ↔ производственный photo.c (50 КиБ байт в байт),
локальный TCP с двумя контроллерами, потери/повторы/задержки/разрывы/сброс, создание окна tkinter.
Настоящие COM-порты, USB-485, плата, проброс 15010 и физическая камера в этих проверках не использовались.

Настройки 485 (команда 12): выберите зарегистрированный контроллер и нажмите
«Настройки 485». По умолчанию основа — Логи/2026-09-21_плата1_конфиг_до_своего_сервера.bin,
снятый read_config.py: 512 байт config_s с CRC16, преобразование не требуется.
Можно открыть другую USB-копию. «Было» относится к этому файлу, не к текущей плате.
Укажите текущий доступный плате адрес НАШЕГО сервера (узел:порт), либо задайте
DOMOVOI_SERVER перед запуском GUI; 0.0.0.0 не подходит. Сервер 1 в пакете заменяется
этим адресом. Проверьте список «было → станет» и только затем отправляйте.
Успех FW подтверждает ответом 12 (штамп/CRC), ошибку — ответом 11; оба видны в GUI.
Остальные поля сохраняются; CRC конфигурации и пакета пересчитываются.
periphery.ini рядом со скриптом — та же UTF-8 таблица, что поставляется с NextConfig.
Скорость одна для шины: коды 0–4 = 115200/57600/38400/19200/9600; байт 174 config_s.
Адрес устройства задаётся его программой, в контроллере указывается такой же;
C328 адреса не имеет и должен быть один на шине. Адрес 0 допустим.
Применение серверных настроек заменяет USB-настройки. Смена состава/скорости
прерывает текущую съёмку; выгрузка уже сохранённого фото продолжается.
